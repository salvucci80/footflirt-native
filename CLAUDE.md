# Claude Code Contract for Footflirt Native

## Branch Naming Conventions
- **Features**: `feat/short-description` (e.g., `feat/user-authentication`)
- **Bug Fixes**: `fix/short-description` (e.g., `fix/login-validation`)
- **Documentation**: `docs/short-description`
- **Refactoring**: `refactor/short-description`

## Commit Message Format
Use conventional commits:
- `feat: add new feature description`
- `fix: resolve bug description`
- `refactor: improve code description`
- `docs: update documentation`
- `test: add or update tests`

## Pull Request Process
1. Create a feature branch from `master`
2. Make changes and commit with conventional commit messages
3. Push the branch to GitHub
4. Create a pull request with a clear description
5. Wait for review before merging

## Merge Strategy
- Use squash merge for cleaner history
- Delete branch after merge
- Keep `master` as the main stable branch

## TypeScript/React Standards
- Follow existing code style in the project
- Use TypeScript for type safety
- Test changes before pushing
- Keep components modular and reusable
